# CycloneAI — Cyclone Impact & Infrastructure Vulnerability Forecaster

An end-to-end platform that answers one operational question: **given this cyclone track, which
critical infrastructure is about to be hit, how hard, and why?**

A Spring Boot domain core ingests NOAA/JTWC-style tracks, interpolates the storm between published
fixes, scores every registered asset, and composes an early-warning advisory — written by Gemini when
a key is configured, by a deterministic template when one is not, and always stating which. The
advisory is published as a CAP 1.2 alert in English, Hindi or Telugu, and can be pushed to a
notification channel when the deployment has one. A React console runs assessments against the live
API and puts the result on a map, behind a public product site that explains the model and starts a
real assessment in one click.

| Tool  | Version used |

### Option A — one command

```bash
./run-demo.sh
```

Starts the API on **8080** and the console on **5173**, waits for the API to answer, and stops both
on Ctrl-C. Logs go to `backend.log` and `frontend.log`.

### Option B — two terminals

```bash
# terminal 1 — API on http://localhost:8080
cd backend
mvn spring-boot:run
```

```bash
# terminal 2 — console on http://localhost:5173
cd frontend
npm install
npm run dev
```

### Option C — containers

```bash
docker compose up --build
```

Console on <http://localhost:5173>, API on <http://localhost:8080>. The console reaches the API
through its own origin (`nginx` proxies `/api`), which is the same shape as the deployed image, so the
composition exercises the deployment rather than a variation of it. Set `APP_JWT_SECRET` in the
environment before using this anywhere shared, and `APP_GEMINI_API_KEY` to put the model in the loop.

### Option D — the AI path, without an API key

```bash
# terminal 1 — a local stand-in for the Gemini endpoint
python3 deploy/mock-gemini/mock_gemini.py
```

```bash
# terminal 2 — the API, pointed at it
cd backend
APP_ADVISORY_MODE=gemini \
APP_GEMINI_API_KEY=mock-key \
APP_GEMINI_ENDPOINT=http://127.0.0.1:9099 \
mvn spring-boot:run
```

Assessments then report `"generator": "gemini"` and the console shows *Generated by
gemini-2.5-flash · N ms*. Set `MOCK_GEMINI_FAULT=truncated` (or `500`, `429`, `blocked`) on the mock
to watch the same assessment degrade to the deterministic advisory with the reason recorded in
provenance. See [AI advisories](#ai-advisories).

### Then

Open <http://localhost:5173> for the product site, then click **Start free demo**. That signs in as
the demo analyst, registers seven coastal assets, runs a real assessment against the Bay of Bengal
storm and lands you in the console at `/app`. OpenAPI documentation is at
<http://localhost:8080/swagger-ui.html>.

### Deploy to a public URL

One command, one service, one origin — the public site, the console and the API behind one URL, so
there is no CORS policy to get wrong and no API hostname to compile into the bundle.

```bash
# from the repository root; gcloud must be authenticated (gcloud auth login)
PROJECT_ID=my-project APP_GEMINI_API_KEY=... ./deploy/cloudrun/deploy.sh
```

The script enables the APIs it needs, creates an Artifact Registry-backed image from the root
`Dockerfile` with Cloud Build, stores the JWT signing key (and the Gemini key, if given) in Secret
Manager, mounts them as environment variables, and prints the service URL. It is idempotent: re-running
deploys the new code and leaves existing secrets untouched, so a live signing key is never rotated by a
redeploy. Without `APP_GEMINI_API_KEY` the deployment still works and issues deterministic advisories.

| Variable | Default | Purpose |
|----------|---------|---------|
| `PROJECT_ID` | *(required)* | Google Cloud project |
| `REGION` | `asia-south1` | Mumbai — closest to the Bay of Bengal |
| `SERVICE` | `cycloneai` | Cloud Run service name |
| `APP_GEMINI_API_KEY` | *(optional)* | Stored in Secret Manager and mounted as `APP_GEMINI_API_KEY` |
| `APP_ADVISORY_MODE` | `auto` | `auto` \| `gemini` \| `deterministic` |
| `ALLOW_UNAUTHENTICATED` | `true` | Leave true for a public demo URL |

After deploying, the URL serves `/` (site), `/app` (console), `/swagger-ui.html` (API docs) and
`/actuator/health`. Before sharing it widely, set `APP_DEMO_*_PASSWORD` so the documented demo
credentials stop working.

## The demo storm

A synthetic reconstruction of a Michaung-like December storm: six-hourly fixes from the southern Bay
of Bengal to landfall near Bapatla, Andhra Pradesh. It is evaluated at `2023-12-05T06:00:00Z`, a
**mid-interval** instant, so the interpolated centre is a modelled position rather than a published
fix — which is the whole point of the track aggregate.

Expected result: **2 critical, 1 high, 1 medium, 3 low.** At the evaluation instant the interpolated
centre carries 48 kt, yet the Bapatla coastal shelter sits 13 nm from it and the NH-16 Krishna delta
span 19 nm, so both trip the distance-based hurricane-force band — the case the model exists to
catch, and one a peak-intensity-only view would miss.

## Credentials and roles

Configured in `backend/src/main/resources/application.yml` under `app.security.users`, overridable by
environment variable. **These are local demo credentials**: replace them and set `APP_JWT_SECRET`
before any deployment a stranger can reach. Passwords may also be supplied as BCrypt hashes.

| Username | Password                | Roles              | Can do |
|----------|-------------------------|--------------------|--------|
| `admin`  | `cyclone-demo-admin`    | ADMIN, ANALYST, VIEWER | Everything, including actuator metrics |
| `analyst`| `cyclone-demo-analyst`  | ANALYST, VIEWER    | Assess, read and write the asset registry |
| `viewer` | `cyclone-demo-viewer`   | VIEWER             | Assess and read only |

Get a token by hand when you want to call the API directly:

```bash
TOKEN=$(curl -s -X POST http://localhost:8080/api/v1/auth/token \
  -H 'Content-Type: application/json' \
  -d '{"username":"analyst","password":"cyclone-demo-analyst"}' | sed -n 's/.*"accessToken":"\([^"]*\)".*/\1/p')

curl -s http://localhost:8080/api/v1/assets -H "Authorization: Bearer $TOKEN"
```

## API

All endpoints except the token endpoint and the health probe require `Authorization: Bearer <token>`.

| Method | Path | Role | Purpose |
|--------|------|------|---------|
| POST | `/api/v1/auth/token` | anonymous | Exchange credentials for a JWT |
| POST | `/api/v1/impact-assessments` | any | Assess a structured track against a list of assets |
| POST | `/api/v1/impact-assessments/from-geojson` | any | Assess a raw GeoJSON feature collection |
| POST | `/api/v1/impact-assessments/cap` | any | The same assessment as a CAP 1.2 XML alert (`Accept: application/cap+xml`) |
| GET | `/api/v1/advisories/channel` | any | Whether an outbound notification channel is configured |
| POST | `/api/v1/advisories/dispatch` | ANALYST, ADMIN | Re-assess and publish the advisory to that channel |
| GET | `/api/v1/assets` | any | List the registry, ordered by identifier |
| GET | `/api/v1/assets/{id}` | any | Fetch one asset |
| POST | `/api/v1/assets` | ANALYST, ADMIN | Register or replace an asset |
| DELETE | `/api/v1/assets/{id}` | ANALYST, ADMIN | Remove an asset |
| GET | `/actuator/health` | anonymous | Liveness, readiness and a domain self-test |
| GET | `/actuator/info`, `/actuator/metrics` | ADMIN | Build info and metrics |
| GET | `/swagger-ui.html`, `/v3/api-docs` | anonymous by default | API documentation |

Failures are RFC 9457 problem documents. Errors name the offending field, and every response carries
an `X-Correlation-Id` header that also appears on the matching log line.

```bash
curl -s -X POST http://localhost:8080/api/v1/impact-assessments \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' -d '{
    "track": {"stormId": "IO-DEMO-01", "points": [
      {"latitude": 13.9, "longitude": 81.8, "windSpeedKnots": 60, "centralPressureMb": 986, "timestamp": "2023-12-04T00:00:00Z"},
      {"latitude": 15.4, "longitude": 80.5, "windSpeedKnots": 55, "centralPressureMb": 990, "timestamp": "2023-12-05T00:00:00Z"}]},
    "assets": [{"id": "AST-1", "name": "Bapatla shelter", "assetType": "MEDICAL_SHELTER",
                "latitude": 15.9, "longitude": 80.47}],
    "evaluationTime": "2023-12-04T12:00:00Z"}'
```

The GeoJSON endpoint accepts what agencies actually publish: `maxwind`/`mslp`/`validtime` (with the
usual aliases), RFC 3339 or ATCF compact times, and skips non-`Point` features such as the drawn
track line and the wind cone.

Every assessment response also carries `advisory` and `advisoryProvenance`:

```json
{
  "stormId": "IO-DEMO-01",
  "advisory": "CYCLONE IMPACT ADVISORY - IO-DEMO-01\n…",
  "advisoryProvenance": {
    "generator": "gemini",
    "model": "gemini-2.5-flash",
    "language": "te",
    "latencyMillis": 412,
    "degraded": false
  },
  "summary": { "countByRisk": { "CRITICAL": 2, "HIGH": 1, "MEDIUM": 1, "LOW": 3 } }
}
```

## AI advisories

The advisory is written by Gemini when a key is configured, and by a deterministic template when one
is not. Both are first-class output: the template is not a placeholder, it is the fallback that keeps
a warning available when a vendor is unreachable, and the response always says which one ran.

**The wiring.** `GeminiAdvisoryClient` is the port; `RestGeminiAdvisoryClient` speaks the documented
`generateContent` HTTP contract (`POST {endpoint}/models/{model}:generateContent`) with the key in
`x-goog-api-key`. It is implemented against HTTP rather than a vendor SDK so the endpoint is
configuration — the same adapter points at the Gemini Developer API, at Vertex AI, or at an internal
gateway that brokers the key — and so the request shape stays auditable in one file. Timeouts are
bounded by configuration (2 s connect, 12 s read) because an advisory that arrives after the briefing
is worth less than a plain one that arrives now.

**What leaves the building.** A rendered prompt: the storm identifier, the validity instant, the
interpolated centre, intensity and pressure, the counts by level, and the exposed assets with their
distances, modelled winds and rule citations. No credentials, no asset coordinates beyond the storm
centre, no operator identity.

**Why a model cannot publish nonsense.** `GeminiAdvisoryGenerator` validates the completion before
anything is published: it must be substantial, plain text, and it must name the storm it describes.
Anything else raises, and `AdvisoryComposer` then publishes the deterministic advisory with the
failure recorded in `advisoryProvenance.detail`. A hallucination or a truncated completion degrades
the wording, never the warning — and the console shows the operator that it happened.

**Configuration** (`application.yml` → `app.ai`, all environment-overridable):

| Variable | Default | Notes |
|----------|---------|-------|
| `APP_ADVISORY_MODE` | `auto` | `auto` uses the model when a key is present; `gemini` requires it (and reports degradation rather than failing the request); `deterministic` never calls it, for air-gapped deployments |
| `APP_GEMINI_API_KEY` | *(empty)* | Absent means deterministic advisories, and every response says so |
| `APP_GEMINI_MODEL` | `gemini-2.5-flash` | Reported in provenance |
| `APP_GEMINI_ENDPOINT` | `https://generativelanguage.googleapis.com/v1beta` | Point at a gateway or at Vertex AI |
| `APP_AI_CONNECT_TIMEOUT` / `APP_AI_READ_TIMEOUT` | `PT2S` / `PT12S` | Bounded on purpose |
| `APP_GEMINI_MAX_OUTPUT_TOKENS` / `APP_GEMINI_TEMPERATURE` | `900` / `0.2` | Low temperature: this is an operations document |

**Verify all three states without a key or a bill**, with `deploy/mock-gemini/mock_gemini.py` — it
runs a real HTTP server, so the adapter, the serialisation and the key header are all exercised for
real. Only the model is fake.

| Mock setting | What the API does |
|--------------|-------------------|
| *(default)* | `"generator": "gemini"`, model name and latency in provenance |
| `MOCK_GEMINI_FAULT=truncated` | HTTP 200 with a complete deterministic advisory, `"degraded": true`, reason recorded |
| `MOCK_GEMINI_FAULT=500` / `429` | Same fallback, with the status in the detail |
| `MOCK_GEMINI_FAULT=blocked` | Same fallback, reported as a safety block |
| no key configured at all | `"generator": "deterministic"`, `"degraded": false`, and a detail explaining that no model is configured |

## Reaching people: CAP 1.2, languages, dispatch

An advisory that stays inside the console has not warned anybody, so the assessment is also rendered
as the interchange format other warning systems already speak, in a language the district reads.

- **CAP 1.2** — `POST /api/v1/impact-assessments/cap` returns a Common Alerting Protocol document
  (`application/cap+xml`, with a `Content-Disposition` filename). The storm centre is published as
  the alert area with its screening radius as the CAP circle, and the generator's advisory becomes the
  alert's description and instruction. The console offers it as a download in one click.
- **Languages** — English, Hindi and Telugu (`hi`, `te`), selected per request with `"language"` and
  reported back in provenance. The prose, the headline and the CAP text are written server-side in
  that language rather than translated in the browser, so there is one source of truth for a warning;
  rule citations, asset identifiers and unit symbols stay as issued, because those are what an
  operator types into other systems.
- **Dispatch** — `POST /api/v1/advisories/dispatch` re-assesses on the server (so a client can never
  post arbitrary prose to a messaging provider) and publishes to the configured channel. With no
  channel configured the console says so precisely and enables CAP download instead; dispatch is
  additionally restricted to ANALYST and ADMIN, and rate limited, because it spends a real provider's
  quota and its effects are not reversible.

| Variable | Default | Notes |
|----------|---------|-------|
| `APP_WEBHOOK_ENABLED` | `false` | Set true with a URL to enable publishing |
| `APP_WEBHOOK_URL` | *(empty)* | A messaging gateway, an aggregator, or a control-room webhook |
| `APP_WEBHOOK_TOKEN` | *(empty)* | Sent as a bearer credential when present; never logged |
| `APP_WEBHOOK_CONNECT_TIMEOUT` / `APP_WEBHOOK_READ_TIMEOUT` | `PT2S` / `PT5S` | Bounded on purpose |
| `APP_ALERT_SENDER` / `APP_ALERT_SENDER_NAME` | `cycloneai@localhost` / `CycloneAI screening platform` | CAP sender identity |
| `APP_ALERT_VALIDITY` | `PT24H` | How long a published alert stays valid |

## Security

Implemented in `com.enterprise.cyclone.security` and verified by hand; see the checklist in the
project summary. In short:

- **Authentication** — HS256 JWT via Spring Security's resource server. The signing key is never
  compiled in: absent configuration, a random key is generated and the trade-off is logged. Tokens
  are issuer-validated, so one minted for another environment cannot be replayed.
- **Authorisation** — ADMIN/ANALYST/VIEWER, enforced on the URL patterns, not in controllers.
  Anything unmatched falls through to `authenticated()`, so a new endpoint is protected by default.
- **Rate limiting** — a token bucket keyed by principal, falling back to the socket peer address
  (never `X-Forwarded-For`, which a client can forge). Guards the assessment and token paths, so the
  login endpoint cannot be used to grind passwords.
- **Input handling** — bean validation on every DTO with size caps on all collections and strings,
  a body size limit checked before the body is read, and Jackson parser constraints on nesting depth,
  string length and number length for chunked requests that declare no length.
- **Logging** — one access line per request with method, path, status, duration and principal. Never
  bodies, never headers, because both carry credentials. Correlation ids are validated against a
  character class before being written to a log line.
- **Headers and CORS** — exact-origin CORS with credentials disabled (the API uses a bearer header,
  not a cookie), `X-Content-Type-Options`, `X-Frame-Options: DENY`, `Referrer-Policy`, and a
  `Content-Security-Policy` that names exactly the two third-party origins the console needs (Google
  Fonts, OpenStreetMap tiles) and nothing else; it is `APP_CONTENT_SECURITY_POLICY`-overridable, and
  the deployment's headers are asserted by `BundledSiteTest`.
- **Outbound calls are bounded and attributable** — the Gemini and webhook clients have configured
  connect and read timeouts, send no credentials other than their own key, and their failures are
  recorded in the response rather than swallowed.
- **Actuator** — only health, info and metrics are exposed; health is anonymous for probes, the rest
  needs ADMIN.

## Notes and limitations

- **The exposure model is a screening model.** The wind field decays exponentially with distance
  (75 nm e-folding) and ignores terrain, gust factor, quadrant asymmetry and forecast positional
  uncertainty. It answers "which assets deserve attention first", not "what will the wind be here".
- **The asset registry is in-memory.** It implements a port, so a database is a new adapter rather
  than a change to callers. Assets do not survive a restart.
- **Google Earth Engine is not implemented, and the product site says so.** `GoogleEarthEngineClient`
  is a port with no adapter and no caller; the landing page lists Earth Engine under *What the platform
  does not claim yet*, alongside storm surge and persistent history. What is implemented is the AI
  advisory path, CAP 1.2 output, the three languages and the one-click demo.
- **Assessments and advisories are not persisted.** There is no history: the registry is a port with
  an in-memory adapter, and each assessment is recomputed. Storing them is a new adapter, not a change
  to the domain.
- **The notification channel is a webhook, not an SMS or WhatsApp integration.** It publishes the
  advisory to a configured endpoint; putting a specific provider behind it means implementing
  `AlertDispatcher` against that provider's API.
- **Swagger UI** is public by default for demonstrability; set `APP_API_DOCS_PUBLIC=false` to require
  ADMIN.
